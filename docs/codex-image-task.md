# Codex作業指示：髪型見本イラストの生成と登録

「ヘアみっけ」（小学生の親子向け髪型カタログ）の見本イラストを、髪型ごとに画像生成で作り、アプリに登録する。

## 1. 最初に読むもの

| ファイル | 内容 |
|---|---|
| [illustration-guide.md](illustration-guide.md) | イラストの目的、画風、描写ルール、避ける表現。**必ず守る** |
| [illustration-prompts.md](illustration-prompts.md) | 髪型ごとの生成用の指示文。**この文をそのまま使う** |
| `js/data.js` | 髪型データ。`HM_STYLES` の `params` が標準形、`HM_IMAGES` が画像の登録先 |
| `img/styles/natural-sheet.webp` | できあがり済みの見本（ナチュラルショート）。**画風の基準** |

## 2. 作るもの

- 1つの髪型につき、**正面・真横（左向き）・後ろを左から横一列に並べた1枚の横長画像**を作る。
- 対象は次の9髪型。上から順に進める。ナチュラルショート（`natural`）とキッズツーブロック（`twoblock`）は作成・登録済みなので作らない。

| 順 | ID | 髪型 | 特に確認すること |
|---|---|---|---|
| 済 | `twoblock` | キッズツーブロック | （登録済み。刈り上げのある髪型の判定の基準にする） |
| 1 | `sports` | さっぱりスポーツ刈り | 刈り上げは中くらいで、上の髪となじんでいるか。トップが立ちすぎていないか |
| 2 | `veryshort` | ベリーショート | 前髪がまゆ上で、おでこが少し見えるか。丸いシルエットか |
| 3 | `buzz` | ボウズ風ベリーショート | 全体がとても短く、頭の丸みに沿っているか。地肌が白く見えていないか |
| 4 | `mash` | マッシュ | 前髪〜サイドが丸くつながっているか。おかっぱ風に重くなりすぎていないか |
| 5 | `sidepart` | 横流しショート | 前髪を下ろして横に流しているか（標準形。額を出す形ではない） |
| 6 | `centerpart` | センターパート | 分け目がまん中で、前髪が目にかかっていないか |
| 7 | `longmash` | 長めマッシュ | 耳が隠れているか。刈り上げがないか。襟足が長めで内側に丸くおさまっているか |
| 8 | `upbang` | アップバング | 前髪をふんわり上げておでこを出しているか。ツンツンに立てすぎていないか |
| 9 | `softmohi` | ソフトモヒカン | トップ中央が少し長く立っているか。極端なモヒカンになっていないか |

### 画風をそろえる

- 画風、顔立ち、線の太さ、髪の塗り方（黒の線と控えめなハッチング）は `img/styles/natural-sheet.webp` に合わせる。カタログ全体で同じ子どもに見えるようにする。
- 刈り上げの描き方（短い部分の質感、下に向かって薄くなじむ表現、上の髪のかぶせ方）は `img/styles/twoblock-sheet.png` に合わせる。
- ただし、この見本の次の2点は**まねしない**。
  - 目が大きく、瞳に強い光が入っている → 目は小さめで、光は控えめにする
  - 頭頂部のはねた毛（アホ毛） → 入れない
- 描く範囲は頭から首まで（肩の線まで）。服は描かない。

### 使ってはいけないもの

- Web上のヘアスタイル写真や、`docs/references.csv` にあるURL先の画像は、**生成ツールへ入力・参照させない。** 利用条件が確認できていないため、特徴を文章にした `illustration-prompts.md` だけを使う。
- 画像の中に、文字、ラベル（「正面」など）、ロゴを入れない。

## 3. 手順（1髪型ごと）

1. `docs/illustration-prompts.md` から、その髪型の指示文（```text のブロック）をそのまま使い、画像を生成する。横長（3:2以上）にする。
2. `img/styles/<ID>-sheet.png` として保存する（例：`img/styles/twoblock-sheet.png`）。
3. 3枚に分割する（Windows PowerShell）。

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/split-sheet.ps1 -src img/styles/twoblock-sheet.png -outDir img/styles -prefix twoblock
   ```

   - `<ID>-front.png`、`<ID>-side.png`、`<ID>-back.png` ができる（同じ大きさ・同じ高さ、縦横比10:11）。
   - 出力の `segments:` が3つに分かれていない、またはエラーになる場合は、3つの絵が近すぎるか重なっている。絵と絵のあいだを広くあけるよう指示して生成し直す。
4. 4章のチェックをすべて確かめる。1つでも満たさなければ、どこが違うかを指示文に書き足して生成し直す（1髪型につき最大3回）。
   - 3回とも合格しなかった場合は、いちばん良かった案を `<ID>-sheet.png` として残し、分割もしておく。登録はせず、6章の報告に「最良案」として書く。
5. 合格したら、`js/data.js` の `window.HM_IMAGES` に追加する。

   ```js
   twoblock: { front: 'img/styles/twoblock-front.png', side: 'img/styles/twoblock-side.png', back: 'img/styles/twoblock-back.png' },
   ```

6. `node serve.js` でアプリを起動し、http://localhost:5173/#/style/<ID> で3方向が切り替わって表示されることを確かめる。

`twoblock` は確認済み。残りの9髪型は、止めずに順に進めてよい。

## 4. チェック項目

分割した3枚と、元の1枚の両方で確かめる。

- [ ] 正面・横・後ろで、同じ子ども・同じ髪型に見える（髪の長さ、ボリューム、毛流れ、分け目、刈り上げの範囲、襟足が一致）
- [ ] 1章の表の「特に確認すること」を満たしている
- [ ] `illustration-prompts.md` の指示（前髪・耳まわり・刈り上げ・襟足）と絵が合っている
- [ ] 刈り上げがある髪型は、横と後ろから高さが分かる。刈り上げがない髪型に、短い部分が描き足されていない
  - 高さは**耳を目印に**比べる（耳の上端より上か、耳の上端くらいか、耳の途中か、耳より下か）。横と後ろで、耳に対する位置がおおむねそろっていれば合格。
  - 後ろの中心で上の髪が少し長く垂れる（V字やU字になる）のは、実際の髪型でもよくあるので不合格にしない。ずれが耳の高さの半分を超えるときだけ作り直す。
- [ ] 主役が髪型で、顔が目立ちすぎていない（目は小さめ、光は控えめ）。`natural-sheet.webp` と同じくらいの目の大きさなら合格
- [ ] はねた毛（アホ毛）、カラー、パーマ、剃り込み、ラインがない
- [ ] 服、背景、文字、ラベル、ロゴがない
- [ ] 画風が `natural-sheet.webp` とそろっている
- [ ] アプリの一覧（小さい表示）でも髪の輪郭が分かる

## 5. 変えてはいけないもの

- `js/data.js` は `window.HM_IMAGES` への追加だけにする。髪型データ（`params`、`variants` など）は変えない。絵とデータが合わないと感じたら、変えずに報告に書く。
- ナチュラルショートの画像（`natural-*`）は作り直さない。
- 刈り上げ比較用の画像（`HM_FADE_IMAGES`）は、この作業では作らない。

## 6. 報告

髪型ごとに、次をまとめて報告する。

| ID | 生成回数 | 合格したか | チェックで気になった点 | データと絵の違い |
|---|---|---|---|---|

- 作り直した場合は、何が問題で、指示文に何を書き足したかも書く。
- 3回で合格しなかった髪型は、登録せずに理由を書く。
