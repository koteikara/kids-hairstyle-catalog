## 0. サービスの考え方

ヘアみっけは、親子が髪型を探す**カタログ**であり、親子と美容師さんが髪型のイメージをそろえる**相談ツール**でもある。

- 子どもが髪型を選び、親子が希望を美容師さんに伝えやすくする。
- 美容師さんは同じイラストと選択肢を使って、違いの説明や、実際にできる形の提案ができる。
- 最後に、親子と美容師さんが合意した内容を、同じ画面で確かめられる。

このため、髪型は「決まった1つの完成形」ではなく、**標準の形＋調整できる項目**として持つ。カードは一方的な「注文票」ではなく、**親子の希望と美容師さんの提案を並べる相談メモ**にする。

## 1. 現在の仕様から変わる点

| 項目 | 現在（プロトタイプ） | これから |
|---|---|---|
| カードの役割 | 親子の希望をまとめた注文票（作ったら読むだけ） | 相談メモ。「希望 → 提案 → 合意」の3段で記録する |
| カードを作る人 | 親子だけ | 親子が作り、来店時は美容師さんも同じ画面で選択肢を動かす（アカウントなし） |
| 調整項目 | 長さ・前髪の長さ・前髪の向き（一部）・耳・襟足・刈り上げ・セット。髪型ごとに候補の印 | 項目の一覧（調整軸）を共通で定義し、髪型ごとに「選べる値」と「標準の値」を持つ。「わからない・おまかせ」を選べる |
| 違いの見せ方 | 刈り上げだけ比較画像あり（後ろ・横の4段階） | 前髪（下ろす／上げる）、耳まわり（残す／短く）、刈り上げ（有無・高さ・短さ）を、同じ頭で比べられる比較画像にする |
| 髪型の説明 | 子ども向け説明、美容師さん向けの伝え方、手入れの手間 | 加えて「再現しやすさ」（必要な長さ、髪質の向き不向き）と「手入れ」（カットの目安の間隔、朝のセット） |
| 利用の入口 | 「予約済み」「これからお店をさがす」の2つ | 加えて「お店で相談中」（来店時の相談モード） |
| 人気の集計 | 閲覧・いいね・保存・カード作成を、髪型ごとに端末の中だけで数える | 行動の種類を増やし（比較を見た、合意した、など）、定義をこの文書で固定する。サーバー集計は将来 |
| 広告・店舗 | 掲載なし（外部リンクのみ） | 変えない。将来掲載する場合のルールを先に決めておく（6章） |

**変えないもの：** 一覧は正面、詳細は正面・横・後ろ、というイラストの基本構成。スマホのWebアプリで、ログインは不要。AIやアカウントの準備を利用者に求めない。

## 3. 親子と美容師さんの利用フロー

### フロー1：予約済みの親子

1. 入口で「もう予約してある」を選ぶ（選ばなくても使える）。
2. カタログで髪型を探し、詳細で3方向と「選べるバリエーション」を見る。
3. 「この髪型で相談メモを作る」→ 調整軸を1つずつ選ぶ。分からない項目は「わからない・おまかせ」にする。
4. ふだんのセットと、美容師さんに相談したいこと（「刈り上げは学校で目立たない程度にしたい」など）を書く。
5. 相談メモができる。来店時に大きく表示して見せるか、共有リンクを送る。

### フロー2：これから美容室を探す親子

1. 入口で「これからお店をさがす」を選ぶ。
2. フロー1の2〜5と同じ手順で相談メモを作る。
3. 相談メモの画面から「お店をさがす」へ進む。子ども対応を確かめるチェックリストと、外部の地図・予約サイトへのリンクを出す。
4. 予約はヘアみっけの外で行う。相談メモは予約の有無にかかわらず使える。

### フロー3：来店時の相談

1. 親子が相談メモを「美容師さんに見せる」表示にする。いちばん大事な項目（髪型名と刈り上げ）を大きく出し、3方向のイラストと、部位ごとの希望を並べる。
2. 美容師さんが「相談する」に切り替える（アカウントなし。親子のスマホをそのまま使う）。
3. 美容師さんが調整軸ごとに比較画像を出して説明する。
   - 例1：前髪を下ろす場合と上げる場合
   - 例2：耳まわりを残す場合と短くする場合
   - 例3：刈り上げの高さと短さ
4. 美容師さんが提案を記録する。
   - 例1：「髪質がやわらかいので、前髪は下ろす形のほうが再現しやすい」
   - 例2：「ツーブロックにするには、上の髪があと2cm必要」
   - 例3：「朝はドライヤーだけで大丈夫」
5. 親子と美容師さんで決めた内容を「これで決定」として合意に記録する。合意した項目は、希望と並べて表示する（どこが変わったか分かる）。
6. 相談メモは親子の端末に残る。次回の来店時は、前回の合意をもとに、少し変えた相談メモを作れる。

> 初期版で3〜5をすべて入れる（8章の決定1）。合意後の相談メモは、共有リンクで美容師さんに渡せる（決定2）。

## 4. データ項目

### 4-1. 髪型（`HM_STYLES` の各要素）

| 項目 | 内容 | 現状 |
|---|---|---|
| `id`, `name`, `catch` | 識別子、髪型名、ひとこと | あり |
| `params` | 標準の形（調整軸ごとの標準の値）。見本イラストに描く形 | あり |
| `variants` | 選べる値（調整軸ごとに値の一覧と、候補にした根拠） | あり（一部の軸） |
| `variantNotes` | まだ選択項目にしていない違いのメモ | あり |
| `fadeNote` | その髪型だけの刈り上げの説明 | あり（スポーツ刈り） |
| `kid` | 子ども向けの説明 | あり |
| `stylist` | 美容師さんへの伝え方 | あり |
| `kidNotes` | 子ども向けに控える点（イラスト制作用） | あり |
| `effort`, `wax`, `tags` | 手入れの手間、ワックス、タグ | あり |
| `requirements` | **追加（2026-10-07 実装）**。再現しやすさの**目安**：必要なトップの長さ（cm）、向いている髪質・注意が必要な髪質（直毛・くせ毛・多い・少ない・つむじが強い）。資料から作り、画面では「目安」と書く | なし |
| `axes` | **追加**。その髪型で使う調整軸の一覧（ショートは刈り上げ、ロングは段や結べるか、など。9章） | なし |
| `audience` | **追加**。「男の子に多い」「女の子に多い」の任意の絞り込み用。子ども本人の性別は記録しない | なし |
| `maintenance` | **追加（2026-10-07 実装）**。カットの目安の間隔（週）、朝のセットの時間の目安 | なし |
| `base` | 人気表示用の仮の数（公開前に削除） | あり |

髪型の画像（`HM_IMAGES`）は、今の「標準の3方向」に加えて、バリエーションごとの画像を持てる形に広げる。

```js
// 例（将来）
HM_IMAGES.sidepart = {
  front: '...', side: '...', back: '...',              // 標準の形
  variants: { 'bangShape=sideup': { front: '...', side: '...', back: '...' } }
};
```

### 4-2. 調整軸（新設：`HM_AXES`）

いまは `HM_LABELS` と画面のコードに分かれている定義を、1つの一覧にまとめる。相談メモ、比較画像、絞り込み、集計は、すべてこの一覧を参照する。

| 軸 | 値 | 比較画像 | 現状 |
|---|---|---|---|
| `top` 全体の長さ | 短め／ふつう／長め（見本より、の相対） | なし（将来） | あり |
| `bangLength` 前髪の長さ | 短め／まゆ毛くらい／まゆ下 | あり（予定） | あり（`bang`） |
| `bangShape` 前髪の向き | 自然に下ろす／そろえる／横に流す／分ける／上げる／立たせる／おでこを出して流す | あり（予定：下ろす／上げる） | あり |
| `ear` 耳まわり | 出す／半分かかる／かくす | あり（予定：残す／短く） | あり |
| `nape` 襟足 | 短め／ふつう／長め | なし（将来） | あり |
| `fadeHeight` 刈り上げの高さ | なし／低め／中くらい／高め（耳を目印に定義） | **あり（後ろ・横）** | あり（`fade`） |
| `fadeLength` 刈り上げの短さ | ぼかす（地肌を見せない）／短め | あり（予定） | なし（新設） |
| `set` ふだんのセット | 何もしない／ドライヤー／ワックス少し／しっかり | なし | あり |

どの軸にも「わからない・おまかせ」（`unsure`）を選べるようにする。相談メモでは「美容師さんと相談」と表示する。長い髪型用の軸（全体の長さ・段・顔まわり・毛量・結べるか）は9章。比較画像は、前髪 → 耳まわり → 刈り上げの短さの順に作る。比較画像は `HM_COMPARE_IMAGES[軸][向き][値]` で持ち、いまの `HM_FADE_IMAGES` はその刈り上げ分として移す。

### 4-3. 相談メモ（いまの「カード」を置きかえる）

```js
{
  schemaVersion: 2,
  id, styleId, createdAt, updatedAt,
  status: 'draft' | 'shown' | 'agreed',       // 作成中／見せた／合意済み
  child: { nickname },                         // 呼び名だけ。本名・顔写真・学校は持たない
  wish: {                                      // 親子の希望
    axes: { fadeHeight: 1, ear: 'out', bangShape: 'unsure', ... },  // 軸ごとの値。'unsure' あり
    set: 'dryer',
    consultLength: true,                       // 細かい長さは相談して決めたい
    note: '学校で刈り上げが目立たない程度に'
  },
  proposals: [                                 // 美容師さんの提案（来店時）
    { axis: 'bangShape', value: 'natural', reason: '髪質がやわらかいので下ろす形が再現しやすい', by: 'stylist', at }
  ],
  agreed: {                                    // 合意した内容
    axes: { ... }, set, note, at, by: 'family+stylist'
  },
  basedOn: 'id'                                // 前回の相談メモをもとに作った場合
}
```

- `by` は初期版では `'family'` か `'stylist'` だけにする。美容師さん用アカウントができたら、ここに美容師さんや店舗の識別子を入れる。
- 共有リンクは、今と同じくURLに内容を入れる形。希望・提案・合意をすべて入れる。呼び名以外の個人情報は入れない。長くなったら（提案が多いなど）、将来のサーバー保存に移す。
- 子どもの髪質や今の長さは持たない。髪質は来店時に美容師さんが見て判断し、必要なら提案の理由に書く。
- いまのカード（`adj`, `set`, `consult`, `nick`, `memo`）は、読み込み時に `wish` へ変換する。**古いカードと、すでに送った共有リンクも開けるようにする**（削除・置換はしない）。

### 4-4. 行動の記録（人気の集計）

## 6. 人気データと収益化のルール

- 行動（閲覧・いいね・保存・相談メモ作成・比較・見せた・合意）は、それぞれ別に記録する。
- 公開時は人気の数字を出さず、「編集部のおすすめ」として並べる。仮の数（`base`）は消す。行動の記録は端末内で続け、将来サーバーで集計する準備にする。
- 「編集部のおすすめ」は編集部が選んだ並びであり、有料枠ではない。将来広告を入れる場合も、広告を「おすすめ」の中に混ぜない。
- 店舗向けに情報を出す場合は、個人が分からない集計データだけにする。
  - 地域は市区町村より細かくしない。
  - 件数が少ない組み合わせは出さない（たとえば10件未満）。
- 有料掲載や広告を行う場合のルール：
  - 「広告」「PR」とカードそのものに書く。
  - 人気順の一覧とは別の枠に置き、人気順には混ぜない。「おすすめ」「注目」という言葉を広告に使わない。
- 予約アフィリエイトは、初期の収益の前提にしない。

## 7. 子どもの写真と位置情報

- 初期版は、子どもの顔写真と正確な位置情報を必須にしない。写真を扱う機能は作らない。
- お店さがしは、外部の地図サービスで検索する形にする（ヘアみっけは位置情報を受け取らない）。
- 写真の取り込みとAI試着は、[future-photo-ai.md](future-photo-ai.md) で別に検討する。

## 9. 女の子の髪型を加えることの影響

v1で女の子の髪型も扱う。最初のペルソナ（10歳の男の子と親）は残したうえで、次を追加・変更する。

### 探し方

- 性別で入口を分けない。まず長さ（ショート／ボブ／ミディアム／ロング）と特徴で探せるようにする。
- 「男の子に多い」「女の子に多い」は任意の絞り込みにとどめ、どの髪型も誰でも選べるようにする。
- 子ども本人の性別は相談メモに記録しない。

### 調整軸

今の軸は、刈り上げなど短い髪型向けに偏っている。長い髪型には、次の軸を追加する。

| 軸 | 値の例 |
|---|---|
| `hairLength` 全体の長さ | あご上／あご／肩上／肩／鎖骨／胸（長い髪型は「見本より」の相対ではなく位置で示す） |
| `layer` 段（レイヤー） | なし（重め）／少し／しっかり |
| `faceFrame` 顔まわり | なし／顔まわりに段 |
| ~~`volume` 毛量~~ | 作らない（下の「決めたこと」） |
| `tie` 結べるか | 結べる長さを残す／こだわらない |

- 髪型ごとに、使う軸を決める（`axes` の一覧を髪型に持たせる）。ショートは刈り上げの軸を使い、ロングは段や結べるかの軸を使う。
- 前髪（長さ・向き）と、ふだんのセットは共通で使う。ロングの「ふだんのセット」には「結ぶ」を加える。

### イラストと参考写真

- 女の子のモデルを1人決め、男の子と同じ画風・同じ3方向・同じ縮尺で描く（[illustration-guide.md](illustration-guide.md) の4章に追記が必要）。
- 長い髪は後ろ姿の情報が多い。後ろの絵で、段、毛先、結べる長さが分かるようにする。
- 参考写真の収集は、男の子と同じルールで行う（子どもに現実的か、控える点を別に記録する）。控える点の例は、カラー、パーマ、強いアイロン巻き、大人びたアレンジ。

### 決めたこと（2026-09-28）

- **髪型は8種類：** 丸みショート、ショートボブ、ぱっつんボブ、切りっぱなしボブ、ミディアム、ぱっつんロング、前髪なしロング、顔まわりレイヤーロング。ID は `g-` から始める。参考写真は [reference-collection-report.md](reference-collection-report.md) の3回目。
- **長さは位置で選ぶ：** `hairLength`（あご上／あご／肩上／肩／鎖骨／胸）。髪型ごとに候補（`variants`）の位置だけを出す。候補がなければ、見本とひとつ短い位置を出す。
- **結ぶ・編むはセットの選択肢にとどめる：** 「ふだんのセット」に「結ぶ」を加えた（女の子の髪型ではワックスの選択肢を出さない）。編み込みなどのアレンジは扱わない。
- **毛量（`volume`）の軸は作らない：** 段（`layer`）と、美容師さんへの伝え方の文で表す。必要になったら追加する。
- **使う軸は髪型ごと（`axes`）：** 女の子の髪型は `gender: 'girl'`、`group`（short／bob／medium／long）、`axes` を持つ。刈り上げの軸は使わず、`params.fade` は 0（「刈り上げなし」の絞り込みに入る）。
- **比較画像：** 前髪・耳まわり・刈り上げの比較画像は男の子のモデルなので、女の子の髪型では出さない。女の子用の比較（長さの位置など）は見本イラストができてから検討する。
- **髪質から探す（2026-10-07）：** 「しぼりこみ」の「髪質（目安）」で選ぶと、その髪質で「注意」の髪型を外す（複数なら、すべてに合う髪型）。ならび順「髪質に合う順」は、選んだ髪質（なければ5種類すべて）で 向いている2点・ふつう1点・注意0点 の合計順。子ども本人の髪質は保存しない。
- **相談メモ：** いちばん大きく出す項目は、女の子の髪型では「全体の長さ」（男の子は刈り上げ）。
